# LLM-first 系統根因分析報告

**日期**: 2026-02-09
**分析範圍**: 為什麼還有答案不正確？為什麼會「部門對，影響錯」？

---

## 🎯 **核心問題回答**

### ❓ **問題 1：為什麼還有答案不正確？**

**答案：三大根本原因**

#### **根因 1：語意不對稱（最嚴重！）**

| 項目 | 附件二（題目） | 附件三（知識庫） |
|------|---------------|-----------------|
| **處理方式** | ✅ LLM-first 萃取 | ❌ 純文字 blob |
| **語意表示** | intent + must_have_terms + topic_tags | [行為準則] [關鍵字] [權責部門] |
| **範例** | intent: "確保工作時間與加班符合法律規範"<br>must_have: ["正常工作時間", "加班", "法律法規"] | [行為準則] 工時<br>[關鍵字] 每週工時、休息日 |

**影響**：
- 題目經過語意提煉，但知識庫是字面文字
- RAG 只能靠「字面相似度」匹配，不夠精準
- **相似度偏低**：57.9 ~ 63.7（黃色區間）

**證據**：
```
題 6（工時）：RAG 相似度 63.7
題 9（歧視）：RAG 相似度 57.9
題 10（標識）：RAG 相似度 58.5
題 13（競爭）：RAG 相似度 62.2
```

---

#### **根因 2：附件三內容問題**

##### **2.1 語意模糊（多個相似條文）**

| 主題 | 筆數 | 問題 | 影響 |
|------|------|------|------|
| 工時 | 5 筆 | 同樣是「工時」，但內容不同 | 題 6 |
| 不歧視 | **14 筆** | 同樣是「不歧視/不騷擾/人道待遇」 | 題 9 |
| 反競爭 | 6 筆 | 部門有「法務」和「企推」 | 題 13 |

**問題**：
- RAG 找到多個候選
- Rerank 難以判斷哪一筆是「真正正確」的
- 最後可能選錯

**實際案例（題 9：不歧視）**：
```
附件三有 14 筆「不歧視」條文：
  列 42-55：都是「不歧視/不騷擾/人道待遇」
  部門：都是「員關」
  關鍵字：年齡、性別、種族、懷孕...（分散在 14 列）

題目：「不得在招募和雇用措施上進行種族、膚色、年齡、性別...歧視」

RAG 找到：列 42-55 都相似
系統選了：其中一列（可能不是最完整的那一列）
結果：部門對（員關），但影響內容不完全匹配
```

##### **2.2 關鍵條文缺失**

| 主題 | 筆數 | 影響 |
|------|------|------|
| **反貪腐** | **0 筆** | 題 13 |

**問題**：
- 題 13 包含「商業道德」（對應「反貪腐」）+ 「不正當競爭」
- 附件三**完全沒有「反貪腐」條文**
- 系統只能找到「反競爭」條文 → 答案不完整

##### **2.3 相似編號混淆**

| 編號 | 筆數 | 問題 |
|------|------|------|
| ISO 14001 | 2 筆 | 與 ISO 14064 分數接近 |
| ISO 14064 | 1 筆 | 干擾 ISO 14001 的選擇 |

**實際案例（題 12：ISO14001）**：
```
題目：「提交 ISO14001 證書」

RAG 返回：
  [0] score=0.971 ✅ ISO 14001（正確！）
  [1] score=0.970 ❌ ISO 14064
  [2] score=0.970 ❌ ISO 50001

問題：
  - Rerank 把 ISO 14064 升級（可能因為它只有 1 筆，更「乾淨」）
  - ISO 14001 被降級
  - 最後選了 ISO 14064
```

---

#### **根因 3：Rerank 邏輯問題**

**現象**：
- RAG top-1 經常是正確的（如題 12 的 ISO 14001）
- 但 Rerank 改變了排序，把錯誤的候選升級

**可能原因**：
1. **單一條文加分**：只有 1 筆的條文可能被認為「更精準」
2. **關鍵字匹配偏差**：可能某些關鍵字意外匹配
3. **缺少「完整性」評分**：沒有檢查是否涵蓋題目的所有概念

### ❓ **問題 2：為什麼會「部門對，影響錯」？**

**答案：row_id 綁定有效，但選錯了 row**

#### **綁定機制有效**

✅ **確認**：系統確實保證了 D/E 欄來自同一列

**證據**：
```python
# upload_attachment3_to_rag.py
chunk_text = f"""[row_id] {row_id}
[類別] {a_col}
[行為準則] {b_col}
[關鍵字] {c_col}
[條文內容] {d_col}
[權責部門] {e_col}      # ✅ 綁定
[目前現況] {f_col}      # ✅ 綁定
[問卷出處] {g_col}"""
```

#### **但選錯了哪一列**

**問題**：
- 附件三有多個相似條文（如「工時」5 筆、「不歧視」14 筆）
- RAG 返回多個候選列
- Rerank 可能選錯了其中一列

**結果**：
- 部門正確（因為同一主題的條文，部門通常相同）
- 影響不正確（因為選錯了那一列的 F 欄內容）

**實際案例**：
```
題 6（工時）：
  附件三有 5 筆「工時」條文（列 24-28），部門都是「薪酬」
  系統選了：列 24（內容提到 ENSH005 出勤管理）
  正確答案：列 25（內容提到 ENSH077 人權管理）
  結果：部門對（薪酬），影響錯（ENSH005 vs ENSH077）
```

### ❓ **問題 3：應該以「影響」為主，還是「部門」為主？**

**答案：應該以「影響（F 欄）」為主，「部門（E 欄）」為輔**

#### **理由分析**

| 欄位 | 重要性 | 原因 |
|------|--------|------|
| **F 欄（影響）** | **主** | 1. 包含具體的辦法編號（如 ENSH077）<br>2. 包含詳細的現況說明<br>3. 是用戶最關心的「實質內容」 |
| **E 欄（部門）** | **輔** | 1. 通常從「影響」可以推斷出部門<br>2. 同一主題的條文，部門通常相同<br>3. 部門只是「歸屬」，不是「內容」 |

#### **設計建議**

**當前問題**：
- 系統把 E 欄（部門）和 F 欄（影響）視為「同等重要」
- 但實際上，**F 欄才是核心**

**改善方向**：

1. **RAG 查詢時，加重 F 欄權重**
   ```python
   # 當前：[行為準則] + [關鍵字] + [條文內容] 權重相同
   # 改進：[目前現況] 權重最高（因為最接近用戶需求）
   ```

2. **Rerank 時，優先匹配 F 欄內容**
   ```python
   def rerank_by_impact_match(question, candidates):
       """優先匹配「影響」內容，而非「行為準則」"""
       for cand in candidates:
           impact = cand.get("impact", "")
           # 檢查題目的 must_have_terms 是否出現在 impact 中
           impact_score = sum(1 for term in must_have if term in impact)
           cand["impact_score"] = impact_score

       # 按 impact_score 排序
       return sorted(candidates, key=lambda x: x["impact_score"], reverse=True)
   ```

3. **部門作為「驗證」而非「主要依據」**
   ```python
   # 選定候選後，檢查部門是否合理
   if selected_dept != expected_dept:
       log_warning("部門不匹配，可能選錯條文")
   ```

## 🔧 **改善方案（按優先級）**

### ⭐⭐⭐ **高優先級（必須做）**

#### **1. 附件三 LLM-first 正規化**

**目標**：消除「語意不對稱」

**做法**：
```python
# 上傳附件三時，每一列都經過 LLM 萃取
knowledge_item = extract_knowledge_schema_llm(
    row_id=f"A{row_idx}",
    category=a_col,
    behavior=b_col,
    keywords=c_col.split("\n"),
    article=d_col,
    dept=e_col,
    impact=f_col,
    source=g_col
)

# 上傳時包含語意標籤
chunk_text = {
    "row_id": knowledge_item.row_id,
    "category": knowledge_item.category,
    "behavior": knowledge_item.behavior,
    "intent": knowledge_item.intent,        # ✅ 新增：語意意圖
    "topic_tags": knowledge_item.topic_tags,  # ✅ 新增：主題標籤
    "keywords": knowledge_item.keywords,
    "article": knowledge_item.article,
    "dept": knowledge_item.dept,
    "impact": knowledge_item.impact,
    "source": knowledge_item.source
}
```

**預期效果**：
- 題目和知識庫都有 intent + topic_tags
- RAG 相似度從 57~63 提升到 80~95
- 減少「選錯相似條文」的問題

#### **2. 補充缺失條文**

**問題**：
- 反貪腐：0 筆（❌ 完全缺失）
- ISO 14001：2 筆（⚠️ 與 ISO 14064 混淆）

**做法**：
1. 人工檢查附件三
2. 補充「反貪腐」相關條文
3. 明確區分 ISO 14001 vs ISO 14064

---

#### **3. Rerank 改進：多概念覆蓋度評分**

**問題**：
- 題目包含多個概念（如「商業道德 + 競爭」）
- 系統只匹配到一個概念

**做法**：
```python
def multi_concept_coverage_score(question_schema, candidate):
    """檢查候選條文是否涵蓋題目的所有核心概念"""
    must_have = question_schema.must_have_terms
    topic_tags = question_schema.topic_tags

    # 檢查 impact（最重要）
    impact = candidate.get("impact", "")
    matched_in_impact = sum(1 for term in must_have if term in impact)

    # 檢查 behavior
    behavior = candidate.get("behavior", "")
    matched_in_behavior = sum(1 for term in must_have if term in behavior)

    # 涵蓋度
    coverage = (matched_in_impact * 2 + matched_in_behavior) / len(must_have)

    if coverage >= 0.8:  # 涵蓋 80% 以上
        return 20
    elif coverage >= 0.5:
        return 10
    else:
        return -10  # 涵蓋不足，扣分
```

## 🎯 **總結**

### **根本原因（按嚴重程度）**

1. **語意不對稱**（最嚴重）：附件三沒有 LLM 萃取 → 影響所有題目
2. **附件三語意模糊**（嚴重）：多個相似條文 → 影響 5 題
3. **附件三缺失條文**（嚴重）：反貪腐 0 筆 → 影響 1 題
4. **Rerank 選擇偏差**（中等）：多概念題目 → 影響 2 題

### **為什麼「部門對，影響錯」？**

- ✅ row_id 綁定有效（D/E 來自同一列）
- ❌ 但選錯了哪一列（附件三有多個相似條文）
- 💡 應該以「影響（F 欄）」為主，「部門（E 欄）」為輔

### **為什麼還有答案不正確？**

- 不是 LLM-first 方向錯誤
- 而是**附件三沒有同步 LLM-first 處理**
- 一邊是「語意」，一邊是「字面」→ 不對稱！

**這證明：LLM-first 方向完全正確，只需要「兩邊都做」！** 🎯
